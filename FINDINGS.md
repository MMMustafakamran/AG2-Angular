# Findings — AG2-Angular (AG2 Python agent + CopilotKit Angular)
Open doc defects only. A finding is proposed first and added only after the owner approves it (QA-RULES section 6; this set approved by the owner 2026-11-09). Numbers are stable IDs (code cites `FINDINGS.md #N`), so gaps are removed findings.
Stack: `@copilotkit/angular` 0.6.0 (npm latest; declared ^0.6.0), `@copilotkit/runtime` 1.85.0 (declared ^1.85.0), `@ag-ui/client` 1.0.4 (npm latest; declared ^1.0.4, not in the doc's install step), `@angular/core` 22.1.4, `@angular/cdk` 22.2.6, `zod` 4.5.4, `express` 5.2.1, `tsx` 4.23.13, `@tanstack/ai` 1.2.0, `@tanstack/ai-openai` 1.1.1 (Components and surfaces runtime; npm latest); agent: `ag2[ag-ui,openai]` 1.3.0 (ag-ui-protocol 1.0.0) + FastAPI 0.162.2 on Python 3.13.15 (uv); Node 26.7.0, npm 11, Windows 11 Pro. Docs: https://docs.copilotkit.ai/angular/ag2, plus the Angular tab of https://docs.copilotkit.ai/ag2/generative-ui/components* (snapshot 2026-11-09)

## Dev blockers (seen with `ng serve` and normal use of the page)

### [Quickstart](https://docs.copilotkit.ai/angular/ag2/quickstart)
**#1 The AG2 Angular quickstart never shows an AG2 backend or a runtime server.**
- **Doc:** the "Connect the selected agent backend" step renders only a callout ("Configure Copilot Runtime to register this backend as the `default` agent at `/api/copilotkit`. Continue with the selected backend's Copilot Runtime guide …"), with no code. The linked [Copilot Runtime](https://docs.copilotkit.ai/angular/ag2/backend/copilot-runtime) page shows only a Next.js `app/api/copilotkit/[[...slug]]/route.ts` with an example `my_agent: new HttpAgent({ url: "http://localhost:8000/" })`: no AG2 agent and no standalone Node runtime server for an Angular app. "Run the backend, runtime, and Angular app" says "Start the selected agent backend and Copilot Runtime with the commands from its runtime guide", and no page gives those commands.
- **Result:** following the page gives an Angular chat pointed at `http://localhost:8200/api/copilotkit` with nothing behind it. The AG2 agent (`ag2.Agent` + `AGUIStream` mounted on FastAPI), the Node runtime server (`CopilotRuntime` + `createCopilotNodeListener`) and the `HttpAgent` binding (from `@ag-ui/client`, not installed by the page) all have to be guessed.
- **Confirmed by harness:** `backend/main.py` (written from the AG2 React quickstart / ag2-samples) and `frontend/server.ts` make the chat work ("Yes — I'm connected. Quick fun fact: kites were invented in ancient China…"). `POST /agent` without the trailing slash answers `307` and the run dies, so the URL must be `http://localhost:8241/agent/`.

### [A2UI schemas, styling, and recovery](https://docs.copilotkit.ai/angular/ag2/guides/a2ui)
**#2 The catalog the page requires is never defined.**
- **Doc:** "A catalog is required: without one, A2UI stays off even when the runtime enables it", then `provideCopilotKit({ runtimeUrl: "/api/copilotkit", a2ui: { catalog: productCatalog, … } })`; `fixedDefinitions` uses `dynamicString` and `satisfies A2UICatalogDefinitions`; the web-components snippet uses `createAngularCatalog`, `ChildListSchema`, `AcmeBadge`, `PanelComponent`; `beautifulCatalog`, `declarativeCatalog`, `fixedCatalog` are referenced, and the Airport/Arrow/AirlineBadge/PriceTag components are never shown.
- **Error:** `error TS2304: Cannot find name 'productCatalog'.` (also `'dynamicString'`, `'A2UICatalogDefinitions'`, `'createAngularCatalog'`, `'AcmeBadge'`, `'PanelComponent'`, `'ChildListSchema'`; `ng serve` type-checks, so the app doesn't build). Without the catalog: `[CopilotKit] The runtime enables A2UI, but no a2ui.catalog is configured, so A2UI stays off.` and nothing renders.

### [Voice and multimodal input](https://docs.copilotkit.ai/angular/ag2/guides/voice-multimodal)
**#3 Voice can't be set up: the transcription backend is never shown.**
- **Doc:** "Follow the [Voice backend setup](/angular/ag2/guides/voice-multimodal#backend) to add a dedicated Runtime route and transcription service."
- **Result:** the link points to the same page, and there's no `#backend` anchor on it. No route or `transcriptionService` code is shown, so `/info` reports `"audioFileTranscriptionEnabled":false` and the chat has no mic button. Attachments work ("The chart is titled "Quarterly revenue." Q4 comes to 300.").

### [Shared state and agent context](https://docs.copilotkit.ai/angular/ag2/guides/shared-state)
**#4 The agent can't read the state the app writes: the page never shows how an AG2 agent uses it.**
- **Doc:** "Agent and application both read and write the value | `injectAgentStore` and `agent.setState`", with `WorkspaceComponent.setPriority()` calling `agent.setState({ ...current, priority })`. The page shows no AG2-side code for reading that state.
- **Result:** after "Mark high priority" the workspace shows `Priority: high`, but asked "What is the priority set to right now?" the agent says it doesn't have access to any priority (e.g. "I don't have access to a "priority" field"). Every try (CI runs and local runs). AG2 1.3.0's `AGUIStream` does copy the client state into the agent's context variables (`ag2/ag_ui/stream.py`: `initial_state = client_state | dict(agent.variables) | command.variables`), but nothing puts those variables into the model's prompt, and the page never shows how to do that for AG2.

### [Sub-agents](https://docs.copilotkit.ai/angular/ag2/multi-agent/subagents)
**#5 The sub-agents code can't be run: it imports modules the page never shows, and the frontend code is React.**
- **Doc:** "Setting up sub-agents" has no setup steps. The page's Code tab (`subagents.py`, the complete file with `supervisor = Agent(...)` and `subagents_app.mount("", stream.build_asgi())`) and the two snippets below it all do `from ._loop_cap import loop_cap` and `from ._state import publish_state`; neither module is shown anywhere. The Code tab's frontend files are React (`page.tsx`, `delegation-log.tsx`, `route.ts`) on the Angular page; the Angular snippet calls `readDelegations(...)` and `subAgentRendererConfig(name)`, which are never defined. The snippet's Python block is printed twice.
- **Error:** `ModuleNotFoundError: No module named 'src.agents._loop_cap'` (Code-tab file saved as `src/agents/subagents.py`, verbatim). Nothing can be served, and there is no Angular code for the delegation log.

### [Native generative UI](https://docs.copilotkit.ai/angular/ag2/guides/generative-ui-components) (in-content: linked from Frontend tools and generative UI, and Using the Angular docs)

### [Components and surfaces](https://docs.copilotkit.ai/ag2/generative-ui/components) · [Surfaces](https://docs.copilotkit.ai/ag2/generative-ui/components/surfaces) · [Catalogs](https://docs.copilotkit.ai/ag2/generative-ui/components/catalogs) · [Standard catalog](https://docs.copilotkit.ai/generative-ui/components/standard-catalog) · [State and actions](https://docs.copilotkit.ai/ag2/generative-ui/components/state-and-actions) · [Theming](https://docs.copilotkit.ai/ag2/generative-ui/components/theming) · [Transports](https://docs.copilotkit.ai/ag2/generative-ui/components/transports) · [Markdown mode](https://docs.copilotkit.ai/ag2/generative-ui/components/markdown-mode) · [Adopt from A2UI](https://docs.copilotkit.ai/ag2/generative-ui/components/from-a2ui) (Angular tab; in-content, announced by the team)
**#14 None of the Angular code on these pages compiles: `@copilotkit/angular/generative-ui` doesn't exist.**
- **Doc:** every Angular tab imports from `@copilotkit/angular/generative-ui`: `import { provideGenerativeUI, standardUI } from "@copilotkit/angular/generative-ui";` (Components step 3, Standard catalog, Markdown mode), `CopilotGenerativeUISurface` (Surfaces), `createGenerativeUI`, `CopilotGenerativeUIChildren`, `GenerativeUIComponentInputs`, `exportA2UICatalog` (Catalogs, Standard catalog, Adopt from A2UI), `connectGenerativeUIState`, `registerGenerativeUIFunction`, `GenerativeUIEventHandler` (State and actions), `GenerativeUITheme` (Theming); Transports shows only `provideGenerativeUI({ ui: standardUI, ... })` calls.
- **Error:** `error TS2307: Cannot find module '@copilotkit/angular/generative-ui' or its corresponding type declarations.` on every page (`npx tsc -p frontend/doc-verbatim/cmp-<page>`). `@copilotkit/angular` 0.6.0 (npm `latest`; no `next` tag, the only other tag is `canary` 0.3.2) exports only `.`, `./a2ui`, `./mcp-apps`, `./styles.css`. The code exists only on CopilotKit `main` (`packages/angular/src/generative-ui/`), unreleased. `ng serve` type-checks, so the app doesn't build with any of it.
- **Result:** without the provider, asking for UI gets plain text or a code block (e.g. "Render a Card with the title Hello" -> "Here's a simple Card component: jsx `<Card title="Hello">…`"), never a rendered component, on all 8 child pages, 3 probe runs each. Same entry point as #6.

**#15 The Components page's "Try it" runtime never answers: its `server.ts` won't start in an Angular app, and its agent fails every run.**
- **Doc:** Angular tab, step 2: "the runtime is a small Node server next to the app. Start it with `npx tsx server.ts`." `server.ts` imports `chat` from `@tanstack/ai` and `openaiText` from `@tanstack/ai-openai`, and the factory calls `return chat({ adapter: openaiText("gpt-6-luna"), messages, systemPrompts: [...], tools, abortController })`. The page shows no AG2 agent at all (the agent is a TanStack `BuiltInAgent`), and says "Your agent must pass the run's tools and context to its model, as in step 2" without saying how for AG2.
- **Error:** `Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: No "exports" main defined in …/node_modules/@tanstack/ai/package.json` (`npx tsx server.ts` in an Angular workspace: no `"type": "module"`, and `@tanstack/ai` 1.2.0 / `@tanstack/ai-openai` 1.1.1 export ESM only). Saved as `.mts` (HARNESS), the server starts but every run fails: `RUN_ERROR` "chat() needs a threadId. Pass a non-empty string, for example the id of the conversation." The chat shows the user message and nothing else, no error on screen (3 probe runs).
- **Confirmed by harness:** `frontend/components-runtime.mts` (the `.mts` copy) starts on :8242; a direct AG-UI request gets the same `RUN_ERROR`.

## Minor notes
- #7 Frontend tools: the browser `getWeather` tool fetches `/api/weather?city=…`, an endpoint no page shows; the render-only `registerRenderToolCall` variant assumes a backend `getWeather` tool the page doesn't show either.
- #9 WebMCP: `searchOrders(status)` is never defined (`error TS2304: Cannot find name 'searchOrders'.`, so `ng serve` won't build until a helper is added). With a helper, the tool registers on `document.modelContext` (Chromium with `WebMCPTesting`).
- #10 Authentication: `readSessionToken`, `sessionToken` and `verifySession` are app-specific placeholders, never defined, and the snippets have no imports. With trivial helpers the `onRequest` hook works (signed out `401 Unauthorized`, signed in a reply).
- #11 Quickstart: the install step doesn't add `@ag-ui/client` (needed for `HttpAgent` in the runtime).
- #13 Inspector: "**[Inspector](/angular/ag2/inspector)** is the page to read for what the panes show" links to the page itself.
- #16 Components and surfaces pages: snippets use names they never define or import: `Product` and `./product-row.component` (Surfaces), `MyFallback` (Surfaces), `cartUI`, `Hero`, `appUI`, `fs` (Catalogs), `ProductCard`, `productSchema` (Standard catalog), `CartStore` / `./cart.store` (State and actions), `Airport`, `Arrow` (Adopt from A2UI); `z` and `createGenerativeUI` are not imported in State and actions / Adopt from A2UI; the product-page snippet has no imports. State and actions declares `export const shopUI` twice over two blocks.
- #17 Native generative UI links to the Components and surfaces pages at `/angular/ag2/generative-ui/components/*` (Components, Surfaces, Catalogs, State and actions, Theming, Transports, Markdown mode): all 404. The pages exist only under `/ag2/...` with the Angular tab; `/ag2/generative-ui/components/standard-catalog` redirects to the framework-less `/generative-ui/components/standard-catalog`.
