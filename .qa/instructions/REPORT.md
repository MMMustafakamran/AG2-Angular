# Report format (team Google Doc)

The final status report is an HTML file the owner pastes straight into the team testing Google Doc. It must match that doc's format exactly.

Source of truth: the team doc's export, `C:\Users\QS\Downloads\_Updated Testing Doc 19th Jun\UpdatedTestingDoc19thJun.html` (LangGraph section). Current model report: `3-output/latest/LangGraph-testing-doc.html` (workspace root, generated by `qa-kit/report/build.py`). `3-output/latest/Antigravity-status.html` uses the team doc's older Antigravity `status` style on purpose (see `qa-kit/report/README.md`); don't copy it for new sections.

## 1. Paste-friendly HTML

- One plain `<table>` per section. Cells are `<td>` with **inline styles** (`border:1px solid #000;padding:6px 8px;vertical-align:top`). No CSS classes, no `<th>`.
- No scripts, no external CSS or fonts, no images, nothing interactive.
- Formatting only with `<b>`, `<a>`, `<br>`. Escape quotes as `&quot;`.

## 2. Structure

- One `<h1>` per framework (e.g. `LangGraph`, `Google Antigravity`).
- `<h2>` sections in the team doc's order: `Quickstarts`, then the guide sections (`React Guides`, `Vue Guides`, `Angular Guides`) for the frontends tested.
- Columns: `Page/Section | <Framework>.<variant> | <Framework>.<variant>`, one result column per variant (e.g. `LangGraph.python | LangGraph.js`). First row is the header, in bold. Leave other teams' columns empty.
- Quickstarts table: one row per frontend (e.g. `JS (React)`, `JS (Vue)`): page cell + result cell.
- Grouping rows (bold label in the first cell), as in the team doc:
  - Section: `Basics | Section | Section`
  - Sub-section: `Chat | Sub section | Sub Section`, `Controlled | Sub-Section | Sub-Section`
  - Child pages under a sub-section are prefixed with `- ` (e.g. `- Components as Tools`).
- Page cell: the page name, linked to the doc page URL.
- Only pages a real user can reach (sidebar, or linked from page content) get a row ([QA-RULES.md](QA-RULES.md) section 9).

## 3. Result cell

In this order, each part separated by `<br>`:

1. **Emoji on its own line:** `✅`, `⚠️` or `❌` (criteria: [QA-RULES.md](QA-RULES.md) section 8). With no clip: `N/A` (plus `Note:` why, e.g. needs the Intelligence Platform) or `–`.
2. **Loom link** to the clip. Link text:
   - ✅: `<Page> - JS` (suffix per variant: `- JS`, `- Vue`), e.g. `Frontend Tools - JS`.
   - ⚠️ / ❌: `Issue`, or `Not Working` when the page is unusable. `Working` is also used in the team doc.
   - Temperature fix clip, when linked: `Issue + Fix ( Backend Code)`.
3. **Notes** (optional, short, plain slightly informal English; not every row has one):
   - `Issue: ...`
   - `Note: ...` (the team doc also writes `Note : ...`)
   - Several minor issues: `Minor Issue: ` then `1) ...`, `2) ...`, each on its own line.
   - Temperature-only pages: ✅ + `Note: the agent code on the page has temperature: 0, gpt-5-mini rejects it (400). Recorded with it removed.`

### Hard-failure block (❌, page unusable)

After the link, in place of an `Issue:` line, one line each:

```
Area/Surface: <page>
Problem: <one line>
Tested context:
OS: Microsoft Windows 11 Pro
Package Manager and version: npm 11 (Node 26.7.0)
“@copilotkit/react-core”: “1.84.1”, “@copilotkit/runtime”: “1.84.1”, …
Loom Video
```

Versions must match the repo's `FINDINGS.md` `Stack:` line.

### Special cells

- Python-only pages: plain text `The code is written only in Python.` (no emoji, no link).

## 4. Clip links before upload

- Until a clip is on Loom, link it as `#LOOM-<clip>`. A final `Clips to upload` section lists `Clip | Placeholder` so each placeholder can be swapped for its Loom URL.
- Approved clips for manual Loom upload are in `3-output/<YYYY-MM-DD>/deliver/`.
