# qa-kit/recorder

Master copy of the autorecorder **core**, taken unchanged from `LangGraph-react/autorecorder/core/`
(2026-11-07, timeline schema 2). Each repo vendors it as `autorecorder/core/`; the repo-specific
parts (`config/*.config.ts`, `actions/`, `cli.ts`) stay in the repo.

| Path | What |
|---|---|
| `core/` | engine, overlays (cursor, Notepad, taskbar, alert dialog), IDE generator, CLI-flow cast player, console capture, failure evidence, doctor, timeline v2 |
| `core/CORE_MANIFEST.json` | sha256 (first 16 hex chars, LF-normalised) per core file |
| `core-history.txt` | hashes of earlier core versions sync.sh may overwrite |
| `scripts/core-manifest.mjs` | `--check` / `--write` / `--diff <other>/autorecorder` |
| `SCHEMA.md` | contract for `<clip>.timeline.json` (schema 2), `<clip>.events.jsonl`, `<clip>.frames/` |

Rules for clips: [instructions/AUTORECORDER.md](../../instructions/AUTORECORDER.md).

## What core imports from the repo

`core/` is framework-neutral but not standalone. It imports `../config/project.config`,
`../config/pages.config`, `../config/selectors.config`, `../config/cli.config` and `../actions`
(the page handlers). So it only builds inside a repo's `autorecorder/` folder, next to those.

## Porting into a repo

```sh
node 2-shared/qa-kit/recorder/scripts/core-manifest.mjs --diff <repo>/autorecorder   # what differs
bash 2-shared/qa-kit/sync.sh <repo>                     # writes <repo>/.qa/ and <repo>/autorecorder/core/
cd <repo>/autorecorder && npx tsc --noEmit && npm test && npm run core:check
```

Never edit `core/` in a repo: `<repo>/autorecorder/core/` is generated by `sync.sh` from
`qa-kit/recorder/core/`, and sync refuses (and reports) a repo copy with local edits. A deliberate
core change is made **here**, followed by `node scripts/core-manifest.mjs --write`, appending the
replaced files' old hashes to `core-history.txt` (so repos still on that version update cleanly),
and a sync of every repo. Per-repo behaviour belongs in the repo's `config/` or `actions/`.

## Timeline v2 (per-clip evidence)

`core/timeline.ts` writes, beside every `<clip>.webm`: `<clip>.timeline.json` (marks, checkpoints,
keyframes, `durationS`, page), `<clip>.events.jsonl` (actions, console, page errors, failed
requests, navigation, marks, checkpoints) and `<clip>.frames/NNN-<label>.jpg`. Logging only: it
never changes what the doc code does or puts anything on screen. Details: [SCHEMA.md](SCHEMA.md).
These files are what `qa-kit/checks/` and the Haiku review ([instructions/REVIEW.md](../../instructions/REVIEW.md)) read.

## The end-of-clip terminal on failed takes (intentional)

A take that fails ends with a terminal window titled `Error console — <page-id>` running a
**real shell**: node-pty spawns bash (Git Bash on Windows, PowerShell only as a fallback;
`QA_FAILURE_SHELL` overrides) in the repo root, the recorder types ordinary commands into it at
a human rhythm (`ls logs/`, `tail -n 25 <log>` for the server logs this page wrote to, then
`grep -n -i -E --color=always "error|exception|failed|404" <log> | tail -n 8` on the one holding
an error-like line), and every byte the PTY prints is streamed into the window live. Nothing on
screen is written by the recorder: no header, no verdict, no summary. **This is intentional**:
it shows the viewer the real terminal error. Keep it; reviewers must not flag it (red text from
grep or the servers is not an overlay). The browser console is not terminal output and is not
printed there.

Where it comes from:

- `core/engine.ts`, end of the page take: when `recordError` is set, `mark('failure', …)` then
  `showFailureEvidence(…)` (bounded to 90 s; a problem here never hides the original failure).
- `core/engine.ts` `showFailureEvidence()`: writes `videos/logs/<page-id>.error.log` (verdict,
  browser console, log slices; file only), opens the terminal window, runs the shell and saves
  the session as `videos/logs/<page-id>.error-terminal.cast`.
- `core/failure-terminal.ts`: `pickShell()`, `pickLogs()`, `failureCommands()`,
  `runFailureTerminal()`.
- `core/failure-evidence.ts`: `snapshotLogOffsets()` (videos/logs/backend.log, frontend.log and
  every `*.log` in `<repo>/logs/` except record.log / start-all.log), `buildFailureEvidence()`,
  `writeFailureLog()`.

Passing takes never show it. The `failure` mark (detail = the error, ≤ 160 chars) marks where it
starts in the timeline.
